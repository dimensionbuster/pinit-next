# 개발 가이드 (빌드 없이 바로 테스트하기)

릴리스 빌드는 4~7분이 걸립니다. **기능 확인에는 쓰지 마세요.** 아래 디버그 실행을 쓰면
코드를 고치고 10~30초 안에 실제 앱에서 확인할 수 있습니다.

## 1. 한 줄 실행

```powershell
npm run dev:app
```

- 프런트엔드(TS/CSS): Vite 핫 리로드. 저장하면 열려 있는 창이 바로 갱신됩니다.
- Rust: 저장하면 `tauri dev`가 자동으로 다시 빌드하고 앱을 재시작합니다(증분 빌드 10~30초).
  재시작해도 열려 있던 이미지 창은 **레이아웃 복원**으로 같은 자리에 다시 뜹니다.
- 처음 한 번만 컴파일이 오래 걸립니다(수 분). 이후는 증분입니다.
- 종료: 터미널에서 `Ctrl+C` (또는 트레이 → 종료).

설정 창 제목이 **"PinIt (DEV)"** 이면 디버그 앱입니다.

## 2. 실사용 앱과 완전히 분리되어 있습니다

| | 디버그(`npm run dev:app`) | 실사용(포터블/설치) |
|---|---|---|
| 앱 식별자 | `com.pinit.next.dev` | `com.pinit.next` |
| 단일 인스턴스 잠금 | 별도 → **동시에 실행 가능** | 별도 |
| 설정·레이아웃·캐시 | `%APPDATA%\com.pinit.next.dev` , `%LOCALAPPDATA%\com.pinit.next.dev` | 포터블은 exe 옆 `PinIt-data\` |
| 브라우저 연동 호스트 이름 | `com.pinit.next.dev` (자기 이름으로만 등록) | `com.pinit.next` |
| 브라우저 확장 | **개발용 확장**(`extension-dev/`, 별도 ID) | 실사용 확장(`extension/`) |

초기화하고 싶으면 위 dev 폴더 두 개를 지우면 됩니다.

## 3. 직접 테스트 체크리스트

테스트 이미지는 설정 창에 **끌어다 놓기**, "파일 선택", 또는 URL 붙여넣기로 엽니다.

- [ ] **배치**: 격자 S/M/L/직접입력, 자율 모드, 시작 모서리 4종 × 가로/세로. 이미지를 10장 이상 연속으로 엽니다.
- [ ] **새 창을 띄울 화면**: 보조 모니터를 선택 → 새 창이 그 모니터에 뜨는지, 크기가 설정값(DIP × 배율)인지.
- [ ] **다시 정렬**: 창을 몇 개 닫은 뒤 누르면 빈자리가 메워지는지. "현재 크기 유지"를 켜고 창 크기를 손으로 바꾼 뒤 눌러서 크기가 유지되는지.
- [ ] **리사이즈**: 창 가장자리를 끌어도 비율로 되돌아가지 않는지. 하단 "창을 이미지 비율에 맞춤" 버튼은 동작하는지.
- [ ] **회전/반전**: `R`, `Shift+R`, `H`, `V`, `Alt+휠`(자유 각도), `0`. 자유 회전 때 이미지 크기가 변하지 않는지.
- [ ] **배경**: 설정 → 이미지 뒤 배경(검정/흰색/색상, 투명도). 열려 있는 창에 즉시 반영되는지. 줌아웃/패닝으로 확인.
- [ ] **레이아웃 저장/불러오기**: 설정 → 레이아웃 → 저장(.pinit) → 모두 닫기 → 불러오기.
- [ ] **복원**: 앱 종료(트레이 → 종료) 후 다시 실행하면 같은 자리에 복원되는지. 창을 X로 닫은 것은 복원되지 않는지.
- [ ] **멀티 모니터/혼합 DPI**: 창을 모니터 사이로 옮기고, 다시 정렬 후 크기가 줄어들지 않는지.
- [ ] **브라우저 연동**: `npm run dev:app`이 `extension-dev/`를 자동 생성합니다(실사용 확장과 코드는 같고 ID·호스트 이름·메뉴 문구만 다름).
  설정 창 → 브라우저 연동 → "확장 폴더 열기"(디버그 앱에서는 `extension-dev/`가 열림) → 브라우저에서 "압축해제된 확장 프로그램"으로 **한 번만** 로드.
  이후 이미지 우클릭 메뉴에 **"PinIt DEV로 열기"** 가 생기며 디버그 앱으로만 연결됩니다. 실사용 확장("PinIt으로 열기")과 **동시에 설치해도 서로 간섭하지 않습니다.**
  `extension/background.js`를 고치면 `npm run dev:app`을 다시 실행해 `extension-dev/`를 갱신하고 브라우저 확장 페이지에서 새로고침하세요.

## 4. 자동 검사 (커밋 전)

```powershell
npm run check     # tsc + JS 단위 테스트 + cargo test --workspace
```

순수 로직(배치, 뷰 변환, 파일 형식, 경로, 프로토콜)은 전부 단위 테스트가 있습니다.
UI를 안 띄우고도 회귀를 잡는 용도입니다.

## 5. 디버깅

- **웹뷰 DevTools**: 디버그 빌드에서는 창에서 우클릭 → *검사*. (뷰어 창은 프레임이 없으니 이미지 위 우클릭)
- **Rust 로그**: 실행한 터미널의 stderr. `eprintln!` 으로 남기면 됩니다.
- **화면을 건드리지 않고 UI 확인**(자동화/원격): 웹뷰 원격 디버그 포트를 엽니다.
  ```powershell
  $env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS="--remote-debugging-port=9340"; npm run dev:app
  ```
  이후 `http://127.0.0.1:9340/json` 에서 각 창의 DevTools 주소를 얻어 CDP로 DOM 조회/스크린샷/IPC 호출을 할 수 있습니다.
  (다른 앱이 쓰는 포트와 겹치지 않게 번호를 바꾸세요.)
- **IPC 직접 호출**(DevTools 콘솔): `await window.__TAURI_INTERNALS__.invoke('list_displays')`

## 6. 코드를 고칠 때 지켜야 할 규칙 (과거에 실제로 사고가 난 것들)

1. **락을 잡는 IPC 커맨드는 반드시 `async`.** 동기 커맨드는 UI 스레드에서 돌고,
   창을 만드는 코드는 서비스 락을 잡은 채 UI 스레드를 기다립니다 → 교착. (`commands.rs` 상단 주석)
2. **창 위치/크기는 `apply_bounds`만 사용.** DPI가 다른 모니터로 옮기면 Windows가 창을 자동으로 줄이므로
   위치→크기 순서로 적용하고 결과를 확인합니다.
3. **좌표는 물리 픽셀, 설정값은 DIP.** DIP→px 변환은 배치 시점에 디스플레이별 배율로만 합니다.
4. **JS로 가는 숫자 id는 2^53 미만.** (모니터 id가 64비트라서 "새 창을 띄울 화면"이 안 먹던 버그)
5. 코어(`crates/pinit-core`)는 Tauri/OS/네트워크 크레이트에 의존하지 않습니다. 새 의존성은 `docs/DEPENDENCIES.md`에 이유를 적습니다.
